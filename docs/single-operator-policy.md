# 運用前提（個人管理型）
更新日: 2026-08-17

## 基本前提
この統合管理システムは、三浦本人が全社人事情報を長期管理するための個人管理型システムとして設計する。

- データ入力・修正・マスタ管理・バックアップ等の実運用者: 1名
- 管理者: 1名
- 他者による入力・更新: 想定しない
- 他者による閲覧: 必要時に1～2名程度の可能性
- 通常データ保存先: Supabase
- 現在のSupabase契約: Free
- Supabase外の常設バックアップ保管先: 現時点では設けない

## 過剰設計として導入しないもの
- 複数管理者による承認フロー
- 入力担当→承認担当のワークフロー
- 部門ごとの複雑な編集権限
- 復旧作業の複数人承認を必須とする仕組み
- 有料PITRを現在必須とする運用
- 外部クラウドストレージを現在必須とする運用

## 1人利用でも維持するもの
- RLS・認証
- 監査ログ
- Schema Version
- Backup Manifest
- Natural Key
- Restore Baseline
- Import履歴
- 誤操作防止
- データ品質検査
- CSV等の可搬性
- 将来別環境へ移行できる論理バックアップ手段

これらは複数利用者のためではなく、長期利用時のデータ破損、操作ミス、将来移行への備えとして維持する。

## 閲覧者
閲覧者を追加する場合でも、原則として参照専用とする。
編集権限を安易に追加せず、必要になった時点で権限設計を見直す。
