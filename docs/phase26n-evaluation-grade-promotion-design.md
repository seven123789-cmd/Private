# Phase26N 人事評価・等級昇格 基礎設計
更新日: 2026-08-17

## 最終等級昇格日の正式ルール
`employee_hr_history_official` を正本とする。

対象は、発令日が確定し、到達等級があり、`event_type` が資格昇格を含む正式履歴。

- 役職変更だけでは更新しない
- 異動だけでは更新しない
- 兼務変更だけでは更新しない
- 同一社員・同一発令日・同一到達等級の重複SOURCEは1回として扱う
- `from_grade → to_grade` が確認できる場合は、数値等級が上がっていることを確認する
- `from_grade` が空でも、正式資料由来の資格昇格で日付・到達等級が確定している履歴は利用できる
- 年度表記だけの未確定日を推測して利用しない

## 社員一覧
将来の社員一覧には以下を追加する。

- 最終等級昇格日
- 昇格後経過（例: 8年4か月）
- 昇格後経過による昇順/降順ソート

経過年月は保存せず、最終等級昇格日と表示基準日から算出する。
正式昇格履歴がない場合は「昇格履歴なし」とする。

## 評価基盤
年度別評価は `evaluation_cycles` と `employee_evaluations` を中心に構成する。
1人運用のため多段階承認者は持たず、操作者追跡は認証と既存audit_logを利用する。

評価 → 昇格判断 → 正式発令 `employee_hr_history_official` → 最終等級昇格日 → 社員一覧
を一本の経路とする。
