# UI/UX改修記録（ui-devブランチ・Claude担当）

## 第1弾：共通デザイン基盤（2026-11-24）

### 方針
- 見た目は `assets/css/ui-refresh.css` を `app.css` の後に読み込んで上書きする。`app.css` 本体は変更していない。
- スマホ用メニューは `assets/js/ui-shell.js`（UI専用）で追加する。業務ロジック、Supabase、既存のIDやイベントには触れない。
- 2ファイルの読み込み行を外せば、改修前の見た目にそのまま戻せる。

### 変更ファイルと影響範囲

| ファイル | 変更内容 | 影響範囲 |
|---|---|---|
| `assets/css/ui-refresh.css`（新規） | 文字サイズ・余白・配色のトークン化、カード・テーブル・フォーム・バッジ・モーダルの統一、画面別の調整、レスポンシブ、印刷用スタイル | 全13画面の見た目のみ |
| `assets/js/ui-shell.js`（新規） | 幅860px以下でトップバーと開閉式メニューを追加 | 全画面の枠。`#sidebar` の中身や `renderSidebar()` は変更なし |
| 全13画面のHTML | 上記2ファイルの読み込みを1行ずつ追加 | 読み込み順：`app.css` → `ui-refresh.css`、`common.js` → `ui-shell.js` |
| `employees.html` | ページ内の`<style>`とインラインstyleをCSSのクラスへ移動（`emp-section-title` / `emp-section-note` / `employee-master-alert`） | ID・role・hidden属性・onclick はそのまま |
| `facility_licenses.html` / `masters.html` | 見出しの重複文字を修正（「事業所資格管理管理管理」→「事業所資格管理」、「各種各種マスタ設定」→「各種マスタ設定」） | 表示文字のみ |

確認したこと：全13画面で `id="..."` の一覧と `on*="..."` 属性の数が改修前と同じ。

### 主な改善点
- **読みやすさ**：9〜11pxだった補足文字・ラベル・バッジを最小12pxに統一。カード見出しは明朝体からゴシック体の太字に変更（ページタイトルの明朝体は維持）。
- **ダッシュボード**：画像ヘッダーを216px→約132pxに縮め、KPIを1画面目に表示。KPIカードに遷移できることを示す「›」を追加。昇格候補リストの崩れ（アイコンと氏名が縦にずれる）を修正。「月次管理」の行は帯状のカードに変更。
- **社員一覧**：センター選択カードを小さくし、選択中を左線で表示。絞り込み6項目とリセットを1行に収めた。表の行の高さを詰め、行クリックできることをホバー時の左線で表示。
- **社員詳細**：氏名帯を画面上部に固定し、スクロール中も対象者がわかるようにした。「人事サマリー」の見出しが縦書き状態に崩れていた問題（人事変更予約パネルが見出し行の中に入るため）を、CSSでパネルを見出しの下に回して解消。
- **フォーム**：必須マークをバッジ化。入力欄のホバー・フォーカス・入力エラー（`:user-invalid`）を統一。モーダルは見出しと保存ボタンを固定し、長いフォームでも保存ボタンが常に見えるようにした。
- **スマホ（860px以下）**：これまではサイドバーが画面全体を占め、本文が下に押し出されていた。トップバーと左から開くメニューに変更。センター選択カードは横スクロールにした。
- **印刷**：サイドバー・ボタン・ページ送りを非表示にし、社員詳細などを紙で確認しやすくした。

### 確認方法
ダミーデータ（架空の社員64名）でSupabaseを模した環境を作り、全13画面をPC（1440px）とスマホ（390px）で表示して、改修前後を比較した。

## システム側への要望事項（変更はしていません）

1. **【至急・セキュリティ】公開リポジトリに実際の社員情報がある**
   `assets/data/employee_master_2026_04.json`（1,871名分の氏名・カナ・生年月日・性別など）と `Supabase Snippet Untitled query (1).csv`（氏名・人事異動の内容）。リポジトリは public で、GitHub Pagesからもダウンロードできる。非公開化、ファイル削除、履歴の書き換えを検討してほしい。なお、JSONは画面の処理では使われていない（`loadEmployeesFromJson` はデモデータを返すだけ）。
2. **社員一覧の行がキーボードで操作できない**
   `<tr onclick>` だけで遷移しているため、Tabキーで選べない。氏名セルを `<a href="employee_detail.html?id=...">` にしてほしい（`employees.js` の変更が必要）。
3. **人事変更予約パネルの見た目がJS側で直接指定されている**
   `employee-assignment-history.js` の `renderSchedules()` で `row.style.marginBottom` を指定し、`<p>` を並べている。クラス（例：`hr-schedule-item`、`hr-schedule-status`）を付けてもらえれば、状態バッジなども含めてCSSで整えられる。
4. **社員詳細で同じ項目が二重に表示されている**
   「所属・人事情報」と「人事サマリー」に等級・役職・入社日・最終昇格日が重複している。サマリー側は「昇格対象・在籍状況・操作」に絞る案を提案する（HTMLとMutationObserverの同期処理の見直しが必要）。
5. **月次管理画面のページ内`<style>`**
   今回は `ui-refresh.css` 側から色を合わせた。月次管理の担当側でページ内`<style>`を外して共通CSSに一本化してよいか確認したい。
6. **使われていないCSSファイル（削除候補）**
   `common.css`、`saas-ui.css`、`ui-common.css`、`visual-upgrade.css`、`sidebar-background-fix.css` は、どの画面からも読み込まれていない。削除してよいか判断してほしい（今回は削除していない）。
7. **社員一覧の表示件数**
   1ページ20件で固定。センター長が自センターを一覧で見られるよう、50件・100件を選べるようにする案（`employees.js` の変更が必要）。
8. **リポジトリ直下のREADME・CHANGELOG類**
   `README_85C.txt` などが直下に多数あり、公開URLからも見える。`docs/` への移動、または公開対象からの除外を提案する。
